# archived Note 规则

本目录保存曾经有效、但已被后续决策替代的历史 Note。默认不读取，也不能把
这里的 Note 当作当前实现依据。

归档 Note 的前三行固定为：

```text
# Agent 笔记：标题

状态：已实现
```

`状态：已实现` 是硬要求（`scripts/verify-agent-notes.mjs` 的 `validateArchivedNote`
按行校验第三行）。原本在 `proposed/` 里的 Note 归档时也改成这一行：归档表达的是
"这篇的结论已经落地或已被取代"，它不再是活的提案，没有必要再区分提议与已实现。
历史视角由下面两行补回来。

状态行之后必须紧跟：

```text
归档日期：yyyy-mm-dd
归档原因：一句话说明它随什么一起失效、决策是否还成立
```

`归档原因` 是给读者看的：没有它，打开一篇讲 `MacServiceContainer` 的 Note 只会
看到"已归档"，却不知道它是被谁取代的。

归档 Note 不再校验 `## 适用范围` 里的路径与 `## 验证` 里的脚本 —— 它描述的代码
可能已经不存在，路径存在性检查只会让归档动作本身失败。

归档内容只用于追溯历史，新的代码修改应读取替代它的 active Note。
