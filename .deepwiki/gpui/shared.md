# Host Shared Crate

`rust/gpui/crates/shared/` is the layer every other gpui crate sits on. It depends on
`gpui-kit`, `lithe-core` (in-process), `serde`, `uuid` and `rust-i18n` — and on **no
other gpui crate**.

| File | Responsibility |
| --- | --- |
| `core_client.rs` | The Core envelope layer: request assembly, response unwrapping, `CoreError` |
| `document.rs` | Versioned-JSON primitives: tolerant per-key parse, unknown-key preservation, atomic write |
| `i18n.rs` | `tr` / `tr_args` wrapper + the wired-key regression table |
| `icons/mod.rs` | Icon rendering helpers (`idea_icon_svg`, `FileIcon`) and the 4-step "how do I reference an icon" contract |
| `icons/idea.rs` | Auto-generated IntelliJ `expui` constant table (79 icons + 16 aliases) |
| `icons/file_icon.rs` | File-type icon theme lookup with a Lucide fallback |
| `workspace_config/mod.rs` | `.lithe/` module root, project identity, session, toolchain layer, "not shared by default" guard |
| `workspace_config/paths.rs` | Single named source for every `.lithe/` member path |
| `workspace_config/project.rs` | `.lithe/project.json` read/write with a stable UUID v4 |
| `workspace_config/session.rs` | `.lithe/session.local.json` |
| `workspace_config/toolchain.rs` | The five toolchain overrides + `project-local > global > auto` resolution |
| `workspace_config/sharing.rs` | Writes `.lithe/` into the local Git exclude file and maintains `.lithe/.gitignore` |
| `workspace_config/test_repo.rs` | `#[cfg(test)]` temp Git repo so guard tests cannot touch the outer repository |
| `locales/` | `lithe.en.yml`, `lithe.zh-CN.yml`, the extraction README, and the vendored `source/*.ts` |

## `core_client.rs` — the only way to call Core

```rust
pub const DEFAULT_TIMEOUT_MILLIS: u64 = 120_000;              // :37
static NEXT_OPERATION_ID: AtomicU64 = AtomicU64::new(1);       // :40

pub struct CoreRequest { /* all fields PRIVATE */ }            // :121-126
pub struct CoreClient;                                         // :191  (unit, Copy)
pub fn core_json(command, payload) -> Result<Option<Value>, CoreError>;  // :241
```

Design decisions worth knowing:

- **Fields are private** so envelope key names cannot be forged by callers (`:115-118`).
- **`id` and `operationId` are always the same value.** When not pinned via
  `with_operation_id`, the value is `format!("lithe-gpui-{command}-{n}")` from the global
  counter. Rationale at `:166-168`: Core uses `operationId` for cancellation and staleness,
  `id` for response correlation, and in this app the two are 1:1.
- **`CoreClient` is a zero-sized named type** so "calling Core" is a searchable name
  rather than a free function (`:188-189`).
- **The call is synchronous.** The module doc is an instruction, not a description:
  callers **must** wrap it in `cx.background_spawn` and must not call it from `render` or
  the UI thread (`:27-28`).

`CoreError` has three variants (`:48-68`): `InvalidResponse`, `Reported { code, message }`,
`MissingData`. Two subtleties:

- `code()` returns `Some` only for `Reported`, and its doc says **do not branch on it**
  (`:71-80`).
- `is_not_a_repository()` is the *only* branch predicate, matching Core's stable signal
  `code == "invalid_request" && message == "Not a Git repository"` (`:82-99`), with the
  message as a const and a test pinning both halves (`:254-286`).

The module deliberately does **not** reinterpret domain-level "success" values — e.g.
`git.status` returning `repositoryRoot: null` (`:44-46`).

## `document.rs` — the JSON document primitive

Every settings-like document in the product uses it. Three properties matter:

1. **`known_keys::<T>()` is derived** from `T::default().serialize()` (`:63-73`). There is
   no hand-written key list, because a missing entry previously produced "written but not
   read back" with **zero diagnostics**.
   Two hard constraints follow: the container needs `#[serde(default)]`, and **no field may
   use `skip_serializing_if`** — otherwise the field is treated as unknown and lost.
2. **`parse` is per-key fault tolerant and never fails** (`:75-166`). A whole-`serde` parse
   is tried first, then a per-key retry, so one bad key falls back without taking the rest
   of the document with it.
3. **Writes are atomic**: a fixed `.tmp` sibling plus `rename` (`:225-266`), which on
   Windows is `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`.

`merge_document` + `preserve_unknown` preserve unknown keys recursively, including inside
nested objects (`:168-223`). `read_document_text` returns `Ok(None)` for a missing file and
never creates anything (`:268-275`).

## Icons

Two independent resolution paths.

**UI icons** — `icons/idea.rs` is generated by `gpui/tools/generate-idea-icons.mjs`
(`--check` verifies it). `struct IdeaIcon { light, dark, has_dark }` holds `AssetSource`
keys, not filesystem paths. Keys are prefixed `ui-icons/idea/` so they cannot collide with
gpui-kit's Lucide `icons/…` keys in the same `AssetSource` (`:13-14`).

**File-type icons** — `icons/file_icon.rs` parses `icon-themes/idea/extension.json`, which
is **embedded at compile time** via `include_str!` so a missing file is a compile error
rather than a silent runtime fallback (`:82-89`). Parsed once per process into a `OnceLock`;
a parse failure is cached, not retried. Lookup order: folders → `expandedFolders` then
`folders` then `idea-folder`; files → `filenames` → **longest-to-shortest** suffix →
`idea-text` (`:156-179, 337-363`).

The theme id is a **compile-time constant** `ACTIVE_FILE_ICON_THEME = "idea"` (`:67-72`),
which is why the other three icon-theme packages are `#[exclude]`d from the binary —
nothing can reach them. Icon-theme switching does not exist today.

**Rendering rules** (measured, and counter-intuitive):

- gpui renders SVGs as an **alpha mask** (`MonochromeSprite`, only `pixel.alpha()` is used),
  so the SVG's own `fill` is discarded. Colour must be set explicitly, and without a
  `text.color` nothing paints at all (the SVG also has no intrinsic size, so a flex child
  collapses to 0 width) — `icons/mod.rs:170-219`.
- `idea_icon_svg_px` requires `rems(..)` not `px(..)` so icons scale with theme font size
  (`:221-240`).
- `struct FileIcon { themed: Option<&'static str>, fallback: IconName }` makes the
  two-source fallback a **type-level** guarantee: the fallback is always populated
  (`:75-99`).
- File-type icons are rendered monochrome via `svg()`, **not `img()`** — `Img`
  intermittently fails to paint in tree rows and status-bar chips (`:262-280`).

## i18n

`rust_i18n::i18n!("locales", fallback = "en")` lives in **this crate's root**
(`lib.rs:47`), and it must stay here. `t!` expands to
`crate::_rust_i18n_try_translate(..)`, a function generated by `i18n!` **in the calling
crate** — so a second `i18n!` in `app` would create a second backend and two sources of
truth (`lib.rs:32-46`, `i18n.rs:16-29`).

- `tr(key) -> SharedString` — `SharedString` because call sites are GPUI `.child(..)` /
  `.text(..)` and `String` is not `IntoElement`.
- `tr_args(key, &[(&str,&str)])` — the frontend placeholder syntax is `{name}` while
  `rust-i18n` 4.2 only understands `%{name}`, so a pure `interpolate` function does a
  sequential `String::replace` and **preserves unknown placeholders verbatim**
  (`i18n.rs:9-12, 115-121, 143-147`).
- Placeholder names come from the locale value, not the call site's `format!`
  (`:83-88`).
- The `WIRED` table (`i18n.rs:161-931`) lists 388 keys. The test
  `every_wired_key_resolves_in_both_locales` takes a mutex (locale is process-global),
  restores the previous locale via a `Drop` guard, and asserts each key exists in zh-CN
  **and matches the pre-wiring hardcoded Chinese string**, and in `en` exists and
  *differs* from zh-CN, with 8 product-name exceptions (`:159-1012`).
- The module doc enumerates what deliberately does **not** go through i18n: internal
  diagnostics, missing keys, placeholder copy, CLI/test fixtures (`:59-82`).

`locales/*.yml` are generated by `gpui/tools/extract-locale.mjs` from the vendored
`locales/source/*.ts`. `locales/README.md` is the regeneration contract (`_version: 2`,
key-first-then-locale, `lithe:` namespace for app strings, `gpui_component:` for component
overrides). The header counts in the yml and README have drifted from the actual key count
— treat the file, not the header, as authoritative.

## `workspace_config/` — `.lithe/`

Four layers, and the project-local layer is expressed by a **filename suffix**
`.local.json` so "should this be committed" is visible in the name and `.gitignore` needs
one rule (`paths.rs:31-32`):

```
built-in defaults  <  global settings.json  <  .lithe/settings.json  <  .lithe/settings.local.json
```

`WorkspaceConfigPaths` (`paths.rs:60-160`) names every member: `project.json`,
`settings.json`, `settings.local.json`, `git.json`, `run/configurations.json`,
`run/generated.json`, `run.local.json` (plus legacy `run/local.json` as a read-only
fallback), `toolchains/requirements.json`, `toolchains.local.json`, `maven/config.json`,
`maven.local.json`, `lsp/language-providers.json`, `session.local.json`, `.gitignore`.

### Project identity

`ProjectManifest { id: Option<String> }`, `PROJECT_MANIFEST_VERSION = 1`. The `id` is a
**UUID v4 generated on first use** and written once; `resolve_project_id` never rewrites an
existing one (`project.rs:249-284`). The UUID shape is asserted (36 chars, version nibble
`4`, variant `8|9|a|b`). Fallback identity is `path_identity(root)` — Core's
`lsp.jdtWorkspaceKey` *without* the optional fingerprint, i.e.
`normalized_workspace_identity + SHA-256` (`:286-302`).

Three subtle rules:

- `id` must **not** use `skip_serializing_if`, otherwise it leaves the `known_keys`-derived
  set and becomes unreadable when another key is bad (`:21-25`).
- A document **newer than supported** is read-only: read it, fall back to path identity,
  never overwrite (`:261-270`).
- Writing without an id is **rejected before the guard runs**, to avoid `id: null`
  clobbering an existing identity (`:124-125, 213-221`).

Fields this module does not own (e.g. Core's `defaultRunConfiguration`) are carried
through verbatim by `document::preserve_unknown`.

### Toolchain layer

Five values across two files: `run.local.json` → `toolchain.java.homePath`,
`toolchain.maven.executablePath`, `toolchain.maven.javaHomePath`; `maven.local.json` →
`settingsPath`, `localRepositoryPath`.

Priority is `project-local > global default > auto-discovery`, implemented exactly once in
`ToolchainPaths::resolve(local, global) -> (Self, OverrideOrigins)` with a single `pick`
closure over all five fields (`toolchain.rs:158-215`). That single implementation is what
guarantees the settings page's "effective value" and the language service's registration
can never disagree.

- **Empty string means "not set here"** — and that is also how you *clear* a value, because
  omitting a field would let unknown-key preservation resurrect it (`:32-37`).
- **Legacy dual read is file-level, not field-level**: `run.local.json` first; if it does
  not exist, `.lithe/run/local.json` instead. A new file always wins even if a value is
  blank (`:38-44`). Writes go only to the new path.
- `ensure_writable` refuses the whole save when the on-disk document declares a newer
  version (`:406-434`).

### Session

`SessionState { open_files, active_file, left_sidebar_visible, top_activity_view,
bottom_kind, bottom_visible, right_view, right_visible }`, version 1,
`MAX_OPEN_FILES = 40` with a documented truncation rule that appends the active file so it
can never be lost (`session.rs:61-76`). `resolve_session_files` skips `outside_root` /
`missing` at **restore** time, not read time (`:256-307`). `is_plain_relative` rejects
empty, absolute (including `C:foo`) and `..` paths (`:309-327`).

### The "default not shared" guard

`sharing.rs` implements the rule that opening a project in Lithe must not commit your
machine-local config. Two gates:

1. `<repo>/.git/info/exclude` via Core `git.write { operation: excludePatterns }`.
2. `.lithe/.gitignore` with `["*.local.json", "run/classes/", "**/*.tmp"]`, append-only
   and idempotent (no write when all are present).

The exclude file's location is **asked from Core** (`git.watchContext` →
`gitCommonDirectory`) because worktrees, submodules and bare repos put it elsewhere
(`:151-171`). `excludePatterns` is chosen over `exclude` specifically so the identical
literal can later be removed byte-for-byte (`:10-25`).

**Every write is read back**; a failure to persist yields `SharingError::NotPersisted`
rather than a false "excluded" (`:174-243`). `share_project_config` removes the literal,
verifies removal by read-back, then stages shareable members; the walk is bounded by
`MAX_WALK_DEPTH = 6` and `MAX_MEMBERS = 512`.

Contract: `.agents/notes/implemented/architecture/2026-09-27-config-document-semantics-and-workspace-config.md`
and the proposed `.agents/notes/proposed/architecture/2026-09-26-workspace-configuration-layers.md`.
