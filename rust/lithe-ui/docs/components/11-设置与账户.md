# 11 · 设置与账户（`settings` / `account`）

`settings` 是"设置窗口里的每一页"，`account` 是登录、注册、资料、团队、计费这一整套账户界面。**设置里只读的快捷键清单 `KeyboardShortcutsList` 在本域**（见第 3 节）。

> 画廊对应 `examples/gallery/pages/settings/`、`examples/gallery/pages/account/`。

## 二、`settings` 用法

### 2.1 骨架：`SettingsLayout` + `SettingsSection` + `SettingsRow`

```rust
SettingsLayout::new("settings", categories)
    .page(active_page_element)
    .on_select(|key, _window, cx| show_page(key, cx));

SettingsSection::new("外观")
    .description("只影响本窗口")
    .row(SettingsRow::new("主题")
        .description("深色调更适合夜间")
        .control(ThemeSelector::new("theme", appearance)));
```

三者构成"页 → 区块 → 行"的三级结构；行右侧的 `.control(..)` 放真正的控件。

### 2.2 外观页

```rust

    .on_change(|appearance, _window, cx| set_appearance(appearance, cx));

    .on_change(|color, _window, cx| set_accent(color, cx));

    .on_change(|size, _window, cx| set_font_size(size, cx));

DensitySelector::new("density", Density::Standard)
    .on_change(|density, _window, cx| set_density(density, cx));
```

`Appearance`（`appearance.rs:18`）是外观模式枚举，它有个 `mode(self, system: Mode) -> Mode`（`:32`）把"跟随系统"解析成具体模式。

### 2.3 主题编辑与导入


## 三、快捷键清单：`KeyboardShortcutsList`（用户点名的那一条）

### 3.1 数据模型与签名

```rust
// settings/shortcuts.rs:15
pub struct Shortcut {
    pub group: SharedString,   // 分组，如 "常规"
    pub name: SharedString,    // 名称，如 "撤销"
    pub keys: SharedString,    // gpui 键语法，如 "cmd-z"
}

// :30
KeyboardShortcutsList::new(shortcuts, search: &Entity<InputState>)
```

`search` 是宿主持有的搜索框状态（组件自己带一个带放大镜图标的 `Input` 在最上方）。

### 3.2 行为（读 `shortcuts.rs:36-95`）

- 过滤规则（`shortcuts.rs:39` 起，内部函数）：把查询按空格拆成若干词，**每个词都必须出现在名称或键里**（不分大小写）才算命中。仓库里的单测（`shortcuts.rs:100-124`）写的是：

```text
"cmd z"     只命中键      -> ["Undo"]
"find cmd"  跨名称与键    -> ["Find"]
""          空查询        -> 全部
```

即"一个词可以只命中键，另一个词命中名称"。业务侧不需要自己调这个过滤函数（它是 `pub(crate)`），把搜索词交给 `InputState` 即可。

- 渲染：按 `group` 顺序分组，组标题是 `TextSize::Xs` + `FontWeight::MEDIUM` + `fg_subtle`；每行左侧是 `Ellipsis::new(name)`（超长省略），右侧是 `KbdCombo::new(&keys)`；行间有 `border_b_1` + `colors.border` 的分隔线。

### 3.3 最小可用示例

```rust
let search = cx.new(|cx| InputState::new(window, cx).placeholder("搜索快捷键"));

KeyboardShortcutsList::new(
    [
        Shortcut { group: "常规".into(), name: "撤销".into(), keys: "cmd-z".into() },
        Shortcut { group: "常规".into(), name: "重做".into(), keys: "cmd-shift-z".into() },
        Shortcut { group: "导航".into(), name: "跳转到行".into(), keys: "cmd-g".into() },
    ],
    &search,
)
```

### 3.4 只读清单 vs 可编辑表

这份清单**只能看，不能改**。文档注释（`shortcuts.rs:22`）明确指向 `editor::KeybindingsEditor` 作为编辑入口。所以设置页的完整做法是：

```rust
if editable {
    KeybindingsEditor::new("keymap", bindings)          // 可编辑：搜索 / 双击录制 / 冲突标记
        .query(query).recording(recording)
        .on_record(..).on_bind(..)
} else {
    KeyboardShortcutsList::new(shortcuts, &search)      // 只读：搜索 + 键帽展示
}
```

## 六、写本域组件时的注意点

1. 设置项的值一律由调用方持有并传入，组件只负责展示与回调；不要在组件里偷偷持久化。
2. "恢复默认"要能逐项恢复（`on_reset`）也要能整体恢复（`on_reset_all`），并先用 `Changed` 把改动项列给用户看。
3. 快捷键展示统一用 `KbdCombo`，键名用 gpui 语法；**只读清单与可编辑表是两个组件**，不要试图让清单也能改。
4. 支付相关校验（`luhn`、`expiry`）是自由函数，表单与后端应共用它们，不要各写一份。
5. 密码、卡号这类敏感字段不要进日志；`ApiKey` 的明文只在 `secret(..)` 里出现一次。
