# 06 · 菜单与浮层（`menus` / `overlays`）

`menus` 管"从一个触发器弹出的菜单"，`overlays` 管"压在内容之上的层"（对话框、气泡卡、灯箱、导览）。两者共用同一套弹出外观来源：`forms::options::surface()`。

> 画廊对应 `examples/gallery/pages/menus/`、`examples/gallery/pages/overlays/`。
> 本域是上一轮菜单视觉改造的落点，`menus/bar.rs` 与 `menus/draw.rs` 的当前实现见第 2、3 节。

## 二、弹出面板的统一外观（必须先懂这一节）

菜单面板、下拉面板、气泡卡全部由同一个内部函数 `forms::options::surface()` 渲染（`forms/options.rs:191`，`pub(crate)`，业务侧调不到，但**它的样式就是所有弹出层的样式来源**，改外观改这一处）：

```rust
// forms/options.rs:191-203
surface(id, cx)  // = div()
    .rounded(Radius::Lg)          // 大圆角
    .bg(colors.overlay)           // 面板底色：overlay 槽位
    .border_1()
    .border_color(colors.border)
    .shadow(Elevation::Floating)  // 浮起阴影
```

菜单在它之上再加自己的排版（`menus/draw.rs:176` 起）：

- `surface((id, "panel-{depth}"), cx)` + `.relative().p_1().flex().flex_col()`
- 宽度：给了 `Menu::width(w)` 就锁死 `min_w = max_w = w`；否则用主题的 `theme.menu_width()`
- 高度：给了 `Menu::max_height(h)` 就 `max_h(h).overflow_y_scroll()`
- 行：见 `menus/draw.rs:18` 的 `row()`，行高 `control_height(Size::Medium)`，高亮用 `colors.hover`
- 分隔线：`div().h_px().my_1().bg(colors.border)`
- 分组标题：`TextSize::Xs` + `FontWeight::MEDIUM` + `colors.fg_subtle`

> **配色槽位提醒**：`overlay` 这个槽位在 `settings/src/theme.rs` 里从主题文件的 `overlay` 键取值（JetBrains 主题里是 `#00000033`，一层遮罩，不是面板色），而它的文档注释写的是"overlay ← popover.background"。**改面板底色时应确认宿主给 `overlay` 的是不透明的 `popover.background`**，否则所有弹出层都会是半透明的。这是上一轮菜单改造的根因结论。

## 三、`MenuBar`（窗口内自绘菜单栏）

### 3.1 构造

```rust
// menus/bar.rs:84
MenuBar::new(id, menus: Vec<OwnedMenu>)
// 例：
MenuBar::new("menu-bar", cx.get_menus().unwrap_or_default())
    .standalone(false);   // 已经在外壳里时传 false
```

- `menus` 就是 `cx.set_menus(..)` 设进去、再用 `cx.get_menus()` 取出来的那批菜单；构造时断言非空（`:85`）。
- `standalone(bool)`（`:99`）决定这条栏**要不要自己画外壳**：
  - `true`（默认）：页顶独立的一条栏，需要自己有底色与下边线；
  - `false`：已经处在宿主已经画好的标题栏里，再画一层同色底和第二条线是多余的。

### 3.2 当前实现的视觉细节（读 `bar.rs:126-199`）

- 根容器：`.w_full().h(control_height(Size::Small)).px_1().bg(colors.title_bar)`，仅当 `standalone` 时追加 `.border_b_1().border_color(colors.border)`；
  - `w_full` 是必需的——flex 行只有标题那么宽，不给它底色会变成一小块；
  - 底色取 `colors.title_bar`，**这是窗口外壳专用槽位，与页面底色 `bg` 不是一回事**。
- 每个标题：`.h(control_height(Size::Small)).px_2().rounded(radius(Radius::Md)).border_1()`；
  - 空闲态：边框透明；
  - 键盘聚焦且当前标题未展开：边框 `colors.focus`；
  - 悬停：`.hover(|s| s.bg(colors.hover))`；
  - 展开中：`.bg(colors.hover)`（`:149`）；
  - 字号：`text_size(TextSize::Sm)`。
- 交互：鼠标按下开/关，鼠标移到已展开的其他标题上会**跟着切过去**（`:159`）；键盘支持 `left`/`right` 在标题间循环并展开、`escape` 关闭。
- 菜单项里的快捷键不是硬编码的：`rows()`（`:26`）通过 `window.highest_precedence_binding_for_action(action)` 取**当前绑定**，用 `MenuItem::keys(..)` 显示。这就是"设置里改了快捷键，菜单里跟着变"的通路。

### 3.3 三种状态命名（与界面设计对齐）

| 状态 | 文字色 | 底色 | 说明 |
| --- | --- | --- | --- |
| idle（空闲） | `fg_muted` | 无 | 未悬停未展开 |
| hover（悬停） | `fg` | `hover` | 指针在上 |
| active-open（展开中） | `fg` | `hover` | 菜单已弹出 |
| disabled（禁用） | `fg_disabled` | 无 | 不可点 |

> 无障碍提示：JetBrains 主题里 `fg_muted` 落在 `hover` / `active` 底色上只有约 4.0:1，达不到 WCAG AA 4.5:1，所以**悬停与展开态必须把文字提到 `fg`**。焦点环用 `colors.focus` 时对比度约 2.5:1，低于 1.4.11 的 3:1，必要时改用 `fg_muted` 作焦点色。禁用态按 WCAG 豁免。

## 五、六种触发器（`menus/hosts.rs`）

### 5.1 `TriggerMenu`：万能底座

```rust
// hosts.rs:97
TriggerMenu::new(id, menu, |open: bool, window, cx| -> AnyElement { ... })
    .open(Some(true))                    // 受控开合：Some(true) 开 / Some(false) 关
    .on_toggle(|open, cx| ...)
    .manual(Some(request_id))            // 手动派发
    .aria_label("更多操作");
```

`trigger` 闭包拿到当前是否展开，返回要画的触发元素。`open(Some(..))` 是**所有者驱动**的那次，不会触发 `on_toggle`（所有者本来就知道自己按了什么）。

### 5.2 `DropdownMenu`

```rust
DropdownMenu::new("branch", "main", branch_menu)

    .variant(ButtonVariant::Ghost)
    .size(Size::Small)
    .tooltip("切换分支");
```

## 六、浮层（`overlays`）

### 6.1 `Dialog` 与三种现成对话框

```rust
Dialog::new("settings")
    .title("设置")
    .detail("只影响当前窗口")
    .fullscreen()                      // 或 .panel() 走面板形态
    .top_inset(px(24.))
    .on_close(|_window, cx| close(cx))
    .action(|close| Button::new("done").label("完成").on_click(move |_, window, cx| {
        close(window, cx);
    }));
```

`Dialog::action(build)`（`dialog.rs:84`）把 `Close`（关闭用的闭包）交给动作构造器，让按钮自己能关掉对话框。

```rust
AlertDialog::new("warn", Severity::Warning, "无法保存", "磁盘已满", |_w, cx| close(cx))
    .label("知道了");

ConfirmDialog::new("del", "删除分支", "该操作不可撤销", |_w, cx| close(cx))
    .confirm("删除")
    .destructive()                     // 确认按钮转危险语气
    .on_confirm(|_window, cx| delete(cx));

PromptDialog::new("rename", "重命名", &name_state, |_w, cx| close(cx))
    .label("新名称")
    .submit("确定")
    .check(|text| if text.is_empty() { Err("不能为空".into()) } else { Ok(()) })
    .on_submit(|text, _window, cx| rename(text, cx));
```

`Severity` 来自 `primitives`（`Info` / `Success` / `Warning` / `Danger` 一类），决定警示框的图标与语气色。

### 6.2 `Popover`

```rust
// 自带一个按钮当触发器（默认 Secondary 语气）
Popover::new("filter", "筛选", |window, cx| filter_body(window, cx))
    .icon(IconName::Filter)
    .variant(ButtonVariant::Ghost)

Popover::with_opener(
```

## 八、写本域组件时的注意点

1. 面板外观**只从 `surface()` 来**，不要另起一套圆角/阴影；改外观改这一处。
2. 菜单项的快捷键要**从当前按键绑定读**（`highest_precedence_binding_for_action`），不要写死，否则设置里改了不会同步。
3. 键盘必须能走通：`Menu::step`（`model.rs:196`）会跳过禁用行并循环，新增交互不要绕过它。
4. 焦点环颜色要满足 3:1（WCAG 1.4.11）；`colors.focus` 在部分主题下不够，需要时换 `fg_muted`。
5. 弹出层关闭要能"把焦点还给触发器"：`Popover::with_opener` 的 `close` 就是干这个的。
6. 文案（"OK"、"Confirm"、"Got it"、"Press again to confirm" 等）目前是英文常量，中文界面应改为 `tr(key)`。
