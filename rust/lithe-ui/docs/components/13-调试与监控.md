# 13 · 调试与监控（`debug` / `devtools` / `tooling` / `dashboard`）

`debug` 是调试器界面，`devtools` 是开发者工具（API 调试、数据库、容器、正则、编码、对比度……），`tooling` 是**给组件库自己用的**自测与检查工具，`dashboard` 是监控仪表盘。

> 画廊对应 `examples/gallery/pages/debug/`、`pages/devtools/`、`pages/tooling/`、`pages/dashboard/`。

### 3.3 正则、编码、对比度（三个高频小工具）

```rust
// 正则：find(pattern, flags, text) -> Result<Vec<Found>, String>
let hits = find(r"(\w+)@(\w+)", &[RegexFlag::Global], &text)?;
RegexTester::new("regex", /* ... */);
// RegexFlag::letter() 取这个标志的简写字母

// 编解码（自由函数）
let b64 = base64(&bytes);
let back = unbase64(&b64)?;
let hx = hex(&bytes);
let raw = unhex(&hx)?;

Encoder::new("encoder", text);        // 面板

// 对比度（WCAG）
let l = luminance(color);
let ratio = contrast(fg, bg);               // 返回比值，如 4.52
let blended = over(semi_transparent, bg);   // 半透明色叠在底色上的实际颜色
let grades = grades(ratio);                 // [(等级名, 是否达标); 4]
ColorContrastChecker::new("contrast", /* ... */).on_change(|(fg, bg), _window, cx| check(fg, bg, cx));
```

> 这四个对比度函数是**组件库自检对比度的标准做法**：半透明文字必须先 `over()` 混到底色上再算 `contrast()`，直接拿带 alpha 的颜色算会偏乐观。`grades()` 返回四档（AA/AAA 的普通字与大字）及是否达标。

## 七、写本域组件时的注意点

1. `tooling` 是**组件库自己的工具**，不要把它打进生产界面；`install_inspector` 只在调试构建里装。
2. 对比度一律用 `contrast()` / `over()` / `grades()` 计算，不靠眼睛估；半透明必须先 `over()`。
3. 剖析类组件（火焰图、时间线）的数据量很大，必须用 `Rc` 传入并在宿主侧做好裁剪，不要在渲染里做聚合。
4. 仪表盘的排布状态（哪些卡片、摆在哪）由调用方持久化，`DashboardGrid::on_change` 只是上报。
5. `debug` 与 `devtools` 的枚举（`DebugState`、`Check`、`PodPhase`、`ContainerState`）是状态显示与语气的唯一来源，加状态时一并加语气映射（如 `status.rs:146` 的 `tone()`、`:136` 的 `words()`）。
