# 10 · 编辑器与终端（`editor` / `terminal` / `language`）

`editor` 是 IDE 部件的合集（编辑器本体、查找、补全、问题面板、搜索、重构、任务、欢迎页……），`terminal` 是伪终端与其周边（命令块、日志、进程），`language` 是语言与语法高亮的注册表（无 UI）。**快捷键编辑器 `KeybindingsEditor` 在本域**（见第 4 节）。

> 画廊对应 `examples/gallery/pages/editor/`、`examples/gallery/pages/terminal/`。

## 二、`CodeEditor`（编辑器本体）

### 2.1 构造与配置

```rust
let editor = cx.new(|cx| {
    CodeEditor::new(initial_text, window, cx)
        .language("rust")
        .line_numbers(LineNumbers::Absolute)      // 枚举：Absolute / Relative / None 一类
        .cursor_shape(CursorShape::Line)
        .tab_size(4)
        .rulers([80, 100])
        .show_whitespace()
        .rainbow_brackets()
        .minimap()
        .sticky_scroll()
        .read_only()
        .auto_completion(true)
        .completion_triggers(".:")
});
```

`CodeEditor::new(text, window, cx)`（`state.rs:212`）是 `Render` + `EventEmitter<EditorEvent>`。运行期改配置用 `set_tab_size(size, cx)`（`:352`）、`set_auto_completion(on, cx)`（`:388`）。

### 2.2 事件

`EditorEvent`（`state.rs:71`）由 `cx.subscribe(&editor, |..|)` 接收，其中 `HoverRequested` 是"指针悬停到某个符号"的请求——由宿主去问语言服务，再把结果塞回编辑器。

### 2.3 与外部的协作约定（读 `state.rs:180-190` 的注释）

编辑器**只保存数据，不负责弹窗**：

- 补全项存在 `completions` 里，**绘制、定位、驱动弹窗都由宿主**负责（用 `CompletionMenu`）；
- 悬停内容存在 `hover` 里，是 `Some` 时由编辑器自己画在内部；
- `hover_symbol` 记录当前指针下的符号范围，保证同一个符号只问一次；
- `set_popup_active(true)` 时，弹窗用的方向键会被**上报而不是被编辑器吃掉**。

### 2.4 `Buffer`

```rust
let buffer = Buffer::new(text);
buffer.set_language(Some(&language));
let spans = buffer.highlight_spans(0..buffer.len());   // (范围, Slot) 列表
buffer.line(3);                                        // 第 3 行文本
let (line, col) = buffer.point(offset);
let offset = buffer.offset(line, col);
```

`Buffer`（`buffer.rs:24`）是纯数据层：`text()` / `len()` / `lines()` / `line_range(line)` / `line_of(offset)` / `next(offset)` / `previous(offset)` / `has_highlighter()`。它不做渲染。

## 四、快捷键编辑器：`KeybindingsEditor`（用户点名的那一条）

### 4.1 数据模型

```rust
// editor/keybindings.rs:19
pub enum KeySource { Default, User }

// :26
pub struct Keybinding {
    pub command: SharedString,     // 命令 id，如 "editor.save"
    pub title: SharedString,       // 显示名，如 "保存"
    pub keys: Option<SharedString>,// gpui 键语法，如 "secondary-s"；None = 未绑定
    pub when: Option<SharedString>,// 生效上下文，如 "Editor"
    pub source: KeySource,         // 来源：默认 / 用户
}
```

### 4.2 冲突检测（自由函数）

```rust
// :35
pub fn conflicts(bindings: &[Keybinding], binding: &Keybinding) -> Vec<SharedString>
```

返回"与它撞键的其他命令的**标题**"。判定规则（`keybindings.rs:39-47`）：排除自己、**键相同且上下文相同时才算冲突**。有单测保证（`keybindings.rs:254-266`）：

```rust
let all = [
    binding("save", "secondary-s", None),
    binding("sort", "secondary-s", None),
    binding("split", "secondary-s", Some("Terminal")),
];
assert_eq!(conflicts(&all, &all[0]), ["sort"]);
assert!(conflicts(&all, &all[2]).is_empty());   // 上下文不同，不算冲突
```

### 4.3 组件签名

```rust
// :65
KeybindingsEditor::new(id, bindings)
    .query(query_text)                  // :77  按标题/命令/键模糊过滤
    .recording(Some(command))           // :83  哪个命令正在录制
    .on_record(|command, window, cx| { /* :89  双击某一行 → 开始录制 */ })
    .on_bind(|command, keystroke, window, cx| { /* :98  录到键（或清空） */ });
```

### 4.4 交互与视觉（读 `keybindings.rs:112-237`）

- 四列：Command / Keybinding / When / Source，列宽按 `theme.label_width()` 乘 `[2.25, 1.5, 1.5, 0.75]`；
- 过滤用 `navigation::fuzzy`，匹配标题、命令或键；
- 行状态：正在录制的行底色 `colors.active`，其余行 `.hover(bg(colors.hover))`；
- **双击一行**进入录制（`:192`，`event.click_count() == 2`），该行的键位格换成 `HotkeyInput::new((id, "keys-{ix}"), None)`；
- 录制结果通过 `on_bind` 回传 `Option<Keystroke>`（`None` 表示 Backspace 清空）；
- 有冲突时行尾显示 `IconName::TriangleAlert`（`colors.warning`），提示文案是 "Also runs …"；
- 来源列：`KeySource::Default` 显示中性 `Badge::new("Default")`，`KeySource::User` 显示 `Badge::new("User").tone(Tone::Info)`。

### 4.5 最小可用示例

```rust
KeybindingsEditor::new("keymap", bindings.clone())
    .query(query.clone())
    .recording(recording.clone())
    .on_record(|command, _window, cx| {
        cx.notify();                       // 宿主把 recording 设成 Some(command.clone())
    })
    .on_bind(|command, keystroke, _window, cx| {
        // keystroke: Option<Keystroke>，None 表示清空
        save_binding(command, keystroke, cx);
        // 保存后可用 conflicts(&bindings, binding) 检查是否撞键并提示
    })
```

## 六、`language`（语法高亮注册）

```rust
// 注册一门语言（程序启动时做一次）
language::register(Language { .. });

// 查询
let all = language::all();
let lang = language::by_extension("rs");

```

`Slot`（`language/mod.rs:48`）是语义类别（关键字、字符串、注释……），组件侧只拿到 `Slot`，由 `editor/syntax.rs` 的 `code_colors` 把 `Slot` 映射到 `syntax` 调色板的具体颜色——**这是语法色的唯一映射点**。

## 八、写本域组件时的注意点

1. `CodeEditor` 与 `Terminal` 都是**实体视图**（`Render`），进树要用实体，不能当一次性元素。
2. 弹窗类 UI（补全、悬停、查找）**由宿主驱动**：编辑器只存数据，方向键在 `set_popup_active` 时上报而不是被吃掉。
3. 快捷键必须走"绑定 → 显示"的单向通路（菜单读 `highest_precedence_binding_for_action`），不要在菜单里写死键名。
4. 冲突判定要带上下文（`when`），同一组键在不同上下文不算冲突。
5. 终端色走 `colors.ansi`，语法色走 `colors.syntax` 且只有 `syntax.rs` 一处做 `Slot → 颜色` 的映射。
6. 本域大量组件有开发期断言（行列从 1 起、缩进至少 1、`cwd` 必须是目录等），传错立刻暴露。
