# 14 · 其余业务域（`feedback` / `calendar` / `documents` / `onboarding` / `misc` / `media` / `mail` / `maps` / `canvas` / `finance` / `generative`）

本文件收的是"不属于前面十三个域、但组件库里确实有"的模块。其中 `feedback`（反馈与状态）、`calendar`（日历）、`documents`（文档与 Markdown）是**跨业务复用的**，其余是按业务场景预置的成套界面。

> 画廊对应各模块同名页面：`examples/gallery/pages/<模块名>/`。

### 吐司（toast）

```rust
// 1) 每个窗口持有一个 Toaster 实体
let toaster = cx.new(|_| Toaster::default());
// 2) 在根布局里放一个 ToastViewport
ToastViewport::new("toasts", &toaster);
// 3) 需要时推一条
toaster.update(cx, |toaster, cx| {
    toaster.push(
        Toast::new("已保存")
            .body("main.rs")
            .severity(Severity::Success)
            .action("撤销", |_window, cx| undo(cx))
            .undo(|_window, cx| undo(cx))     // 带一条会走完的倒计时线
            .stay(Some(Duration::from_secs(4))),   // None = 不自动消失
        cx,
    );
});
```

`stay` 不能传 `Some(Duration::ZERO)`（`toast.rs:79` 会断言）。`Toaster::push` 返回这条吐司的 id，可以提前送走它。

## 十二、写这些域组件时的注意点

1. **`feedback` 是公共底座**：提示、空态、错误、保存/同步状态不要各业务各写一套，统一用这一域。
2. `Toaster` 是实体，**一个窗口一个**，`ToastViewport` 放在根布局里；`stay` 不能为 0。
3. 颜色一律走 `Severity` / `Tone` 这类语气枚举，不要在业务里写死色值。
4. 地图、画布、图表的坐标/视口都由调用方持有，组件只画。
5. 金融与生成式 AI 这两域的组件数量多但结构相似：都是"数据模型 + 一个视图 + 若干回调"，新增时照抄同域既有文件的结构即可。
6. 本域不少文案（如 "Keyboard shortcuts"）目前是英文常量，中文界面应改走 `tr(key)` + `locales/ui.yml`。
