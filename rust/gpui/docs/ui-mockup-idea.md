## 3. 五条改动，逐条拆开

### 变更 1 — 文件标签显示文件类型图标 ✅ **已在真机确认实现，降级为"核尺寸"**

- **图注**：「文件标签栏，但是需要可以显示对应的文件类型图标」
- **真机截图实测**：**已经画出来了**——Lithe 截图的标签栏里 `InpInfoApiAction.java` 左侧就是一个蓝色圆形
  带 `J` 的文件类型图标，`HtFrontInterfaceAp…` / `HtInterfaceApinterf…` 同样有各自的图标。
- **源码落点**：`editor_view.rs:2507-2512` 在标签最左渲染 `buffer.icon`，尺寸 `rems(0.75)` = 12px
  （IDEA 真机的标签图标槽也是 12px）；图标主题默认 `idea-icons`
  （`shared/src/icons/file_icon.rs:68`，与 Windows 前端 `file-icon-semantics.ts:14` 同值）。
- **所以这条只剩两件小事**（要你选）：
  1. **尺寸/间距对齐**：IDEA 的标签图标与文字 gap、图标到标签左缘的 pl 是否与 Lithe 现用
     `pl_2()`(8) + `gap_1p5()`(6) 一致（`editor_view.rs:127-131` 记着这套值来自 Windows 规格）；
  2. **图标主题的完备性**：`idea` 图标主题现嵌 79 张 `expui` SVG
     （`shared/src/icons/idea.rs:12,47`），Java 项目够用；若遇到 `.factpath` / `.classpath` 这类
     没命中的扩展名，会回退 Lucide 单色字形——**要不要补**由你定。
- **未实现**：IDEA 标签栏右侧的「标签切换器下拉 `⌄`」在 Lithe **没有**（`editor_view.rs` 无此项）。

### 变更 2 — 编辑区左边界加「收起侧栏」图标按钮 ★（真新增）

- **图注**：「还是原来的，但文件边框框这里可以点击图标进行收起」
- **IDEA 的做法**：编辑器岛左右边界各有一个贴边的窄按钮（`⇤`/`⇥` 语义），点一下收/放对应的工具窗；
  图标常显浅色、悬停变亮。
- **Lithe 现状**：**没有这个控件**。收放侧栏只能靠左活动栏再点一次当前项，或菜单/键位
  （`workspace.rs:2283` 附近的 `ToggleActivitySidebar` 一类动作有键位）。
- **要加的**：
  - 元素：一条贴边的 24×24 命中区（视觉上是 16×16 图标居中），贴在编辑器岛左边界内侧；
  - 图标来源：`gpui/assets/icon-themes/idea/**` 里找 `expui` 的 collapse/expand 对
    （`idea.rs` 的 `ALL` 清单里目前**没有** `chevronsLeft/Right` 这一对，需要按生成器补两个 SVG，

- **9-③ 图标：一律保持原来的单色，本轮不动**（图注 A3/A6「图标更换」→ **已按维护者口径否决**）：
  > 维护者 2026-09-27 明确：「**图标不要新增，还是原来的单色图标就可以，主要是整体界面的调整**」。

  所以**本轮不换任何图标**，效果图里也把图标画回单色。下面把"为什么本来就是单色"记下来，
  免得下次又有人把它当成 bug 去修：

  **查表层是好的**（两条证据）：
  1. 映射表齐全：`gpui/assets/icon-themes/idea/extension.json:143` `.java → idea-java`、
     `:144` `.xml → idea-xml`、`:220` `pom.xml → idea-maven`、`:222` `.gitignore → idea-gitignore`；
  2. 资产内嵌：`icon-themes/idea/**` 共 104 个文件在二进制里（`app/src/assets.rs:35,312`），
     `file_icon.rs:17-27` 固定查这一套（`ACTIVE_FILE_ICON_THEME = "idea"`）。

  **渲染层是单色，且是刻意取舍**（`shared/src/icons/file_icon.rs:262-281` 的实测记录）：
  - 真源文件类型图标是**彩色**的，本该走 `img()`；**但在本机实测不可行**：
    同一个构建、`rems(1.)`（16px）时 9 行树里只有目录行有字形，放大到 64px 才全部有字形；
    放进状态栏 chip 则**完全不画**（该区域一个非背景像素都没有），颜色也不是原色；
  - 成因指向 gpui 的图片链路：`Img::request_layout` 只在有 `GlobalElementId` 时才取数据
    （`gpui-pre-0.3.6/src/elements/img.rs:289-315`），而文件树行由 `uniform_list` 渲染、
    **没有稳定的全局 id**；
  - 所以走 `svg()`：稳定出图、边缘锐利、颜色由 `theme.muted_foreground` 给，代价就是单色。
    文档里的取舍原话：「优先'画得出来 + 边缘锐利'，把'彩色'留作后续」。

  **如果哪天要做彩色**：那是**换渲染链路**（文档列了两条路：预渲染成 `RenderImage` 走
  `ImageSource::Render`，或用 `gpui::canvas` 自绘），**不是改一个参数**，属独立一件事，不进本轮。

  **顺带一条独立小缺口**（也不是本轮）：语义键没有数据源 —— `filenames` 里的 `\0lithe:java.class` /
  `.interface` / `.enum` / `.annotation` / `.record` / `.exception`（`:214-219`）与 `folders` 里的
  `folder.source-root` / `folder.test-root` / `folder.package`（`:228-241`）都要求 Java 语言服务的结果
  （真机是 `file-icon-semantics.ts` 喂的）。gpui 侧查表前会跳过带 `\0` 的键（`file_icon.rs:43-45`），
  所以类/枚举与"源码根"文件夹拿不到专属图标，落 `defaultFile`（`idea-text`）。
